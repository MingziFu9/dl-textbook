## 情景导入
- 外卖平台每天上万条评论
- 用 1.2 万条已标注评论训练分类器
- 难题：文字怎样变成数字？

::: notes
小林在一家外卖平台的客服部门实习。平台每天收到上万条评论，其中有夸奖，也有投诉：“等了两个小时，饭都凉了”“送餐员态度很差”“分量太少，不会再点了”。客服主管希望差评能被尽快找出来、及时处理，可是靠人一条条看，十几个人也看不完。
主管交给小林一个任务：用平台已经标注好的 1.2 万条评论（每条标了“好评”或“差评”），训练一个模型，自动把新评论分成好评和差评。
小林已经会用神经网络给图片分类了，但文字和图片不一样：图片本来就是一堆数字，文字却是一个个汉字和词语。“好吃”和“美味”意思相近，计算机怎么知道？“好吃”和“不好吃”只差一个字，意思却相反，网络又怎么分辨？
本章先解决“文字怎么变成数字”的问题，再从零训练一个外卖评论分类器；最后认识 BERT 这类预训练语言模型：它们先读了海量的文章，“懂”了语言，再用少量数据稍加训练，就能完成各种文本任务。这和第 7 章的迁移学习是同一个思路。
:::

# 8.1 文本怎么变成数字

## 8.1 文本怎么变成数字
- 四步：分词 → 建词表 → 编号补齐 → 词嵌入

::: notes
把一条评论变成网络能处理的数字，一般分四步：分词、建词表、编号与补齐、词嵌入。
:::

## 8.1.1 分词
- 中文词之间没有空格，要先**分词**
- 常用工具：jieba
- 也可以按字处理，不用分词

::: notes
英文的词和词之间有空格，中文却没有。所以处理中文的第一步，是把句子切成一个个词，叫分词。最常用的中文分词工具是开源的 jieba（结巴分词）：
也可以不分词，直接按字处理（第 6 章实验 6-2 就是按字处理的）。按字处理不需要分词工具，也不会因为分词出错而受影响；按词处理的序列更短，每个单位的意思更完整。两种做法在实际中都很常见。
:::

## 8.1.2 建词表、编号与补齐
- 词表：给每个词一个编号
- 0 号补齐，1 号代表没见过的词
- 短的补 0，长的截断
- 词表只能用**训练集**建

::: notes
建词表：统计训练集中出现过的所有词，给每个词一个编号。出现次数太少的词（比如只出现 1 次）通常不放进词表。另外预留两个特殊编号：0 号给“补齐”，1 号给“未知”（词表里没有的词）。
编号：把每条评论的每个词换成它的编号，比如“豆腐脑 / 味道 / 感觉 / 很 / 一般”变成 [2, 3, 4, 5, 6]。
补齐与截断：网络要求一批数据的长度相同，所以要规定一个最大长度（比如 40 个词）。短的评论在后面补 0，长的评论截掉后面的部分：
注意：词表只能用训练集来建，和第 6 章“标准化只能用训练部分算平均值”是同一个道理，避免偷看测试数据。
:::

## 8.1.3 词嵌入：从编号到向量
- 编号只是代号，不表示意思
- 独热编码：太长、看不出相近
- 词嵌入：短而稠密的向量，相近词相近
- `nn.Embedding(词表大小, 维度)`

::: notes
编号只是一个代号，“3 号词”和“4 号词”并不表示两个词意思相近。早期的做法是独热编码：词表有 4000 个词，每个词就用一个 4000 维的向量表示，只有自己的位置是 1，其余全是 0。它有两个缺点：一是太长、太浪费；二是任意两个词的向量都互相垂直，看不出“好吃”和“美味”比“好吃”和“米饭”更接近。
词嵌入的做法是：给每个词分配一个短的、稠密的向量（比如 64 维），叫词向量，让意思相近的词，向量也相近。在 PyTorch 中，`nn.Embedding` 就是一张“查找表”：第 i 行就是 i 号词的词向量。
这张表里的数是网络的参数，开始是随机数，和其他层一起通过训练学出来。`padding_idx=0` 表示 0 号（补齐）的向量固定为全 0，不参与训练。
:::

## 8.1.4 词向量是怎么学出来的
- Word2Vec：看一个词的“邻居”
- 余弦相似度：只看方向
- 越接近 1，意思越接近

!sim word-vectors

::: notes
词向量可以随着分类任务一起训练，也可以先单独训练好。最著名的单独训练方法是 2013 年提出的 Word2Vec。 它的思路是“看一个词经常和哪些词一起出现”：“好吃”和“美味”经常出现在相似的上下文里（“菜很＿＿”“味道＿＿”），训练后它们的向量就会靠近。
两个词向量有多相近，常用余弦相似度来衡量：
$$\cos(\boldsymbol, \boldsymbol) = \frac{\boldsymbol \cdot \boldsymbol}{|\boldsymbol| \times |\boldsymbol|}$$
分子是点积（对应位置相乘再相加），分母是两个向量长度的乘积。结果在 −1 到 1 之间：越接近 1，方向越一致，意思越接近。它只看方向、不看长短。
:::

## 8.2 案例实战：外卖评论情感分类
- 数据：约 1.2 万条外卖评论
- ① 词袋模型：词向量取平均
- ② LSTM：按顺序读
- 测试集准确率：两者都是 **88.83%**
- 顺序重要的句子，LSTM 判断更合理

::: notes
把评论分成好评、差评，叫情感分类，是最常见的文本分类任务之一。实验 8-2 用 waimai_10k 数据集（约 1.2 万条外卖评论）完成这个项目，比较两种模型：
① 词袋模型：把一条评论中所有词的词向量取平均，再接一个全连接层。它不管词的顺序，就像把词倒进一个袋子里摇一摇。
② LSTM 模型：词向量按顺序送进 LSTM，取读完最后一个真实词时的隐藏状态，接全连接层。
`pack_padded_sequence`（打包）告诉 LSTM 每条评论的真实长度。如果不打包，一条 5 个词的评论后面补了 35 个 0，LSTM 会一直读到第 40 个位置，最后的隐藏状态被一串“补齐”冲淡了。
实验结果（测试集 1987 条）：
两个模型的准确率完全相同。外卖评论大多很短，“好吃”“太慢了”这几个关键词就能决定好坏，顺序不那么重要。但看下面两条自己写的评论，区别就出来了：
两条评论用的词几乎一样，词袋模型给出的结果也差不多；LSTM 则对两种说法给出了不同的判断。人读这两句话，重点往往落在后半句，第二句应该偏好评，LSTM 在这里其实判断反了。这说明：LSTM 能利用顺序，但它学到的规律不一定都对。对短文本，简单的词袋模型往往已经够用，而且快得多。
:::

# 8.3 预训练语言模型：先读万卷书，再做小练习

## 8.3.1 一词多义的难题
- Word2Vec：每个词一个固定向量
- “苹果很甜”和“苹果手机”
- 要结合上下文才知道意思

::: notes
Word2Vec 给每个词一个固定的向量。可是很多词的意思要看上下文：“这家的苹果很甜”和“我的苹果手机没电了”中的“苹果”，意思完全不同；“东西很好，就是太贵了”和“太贵了，东西也不好”中的“好”，分量也不一样。
:::

## 8.3.2 BERT：完形填空练出来的语言能力
- 多层 Transformer 编码器
- **预训练**：海量文章做完形填空
- **微调**：接分类层，用少量数据训练
- 同一个词，不同句子不同向量

::: notes
2018 年，谷歌发布了 BERT。 它是一个多层的 Transformer 编码器（第 6 章），训练分两个阶段：
第一阶段：预训练。用海量的文章（维基百科、新闻、图书……）做“完形填空”：随机遮住句子中 15% 的字，让模型根据上下文猜被遮住的是什么。比如“今天天[遮]很好”，模型要猜出“气”。这个任务不需要人工标注，文章本身就是答案，所以可以用几十亿字来训练。做了大量的完形填空，模型就学会了字词的用法、语法，甚至一些常识。
第二阶段：微调。在 BERT 后面接一个分类层，用你自己的少量标注数据（比如几千条评论）训练几轮，学习率很小，和第 7 章的微调一样。
因为每个字的向量是 Transformer 结合整句话算出来的，同一个“苹果”在不同的句子里会得到不同的向量，一词多义的问题就解决了。这类先用大量文本预训练、再针对具体任务微调的模型，叫预训练语言模型。
:::

## 8.3.3 文本任务的几种做法
- 从零训练：词袋、LSTM
- 预训练模型微调：BERT 系列
- 直接用大模型：写提示词
- 中文模型：hfl 系列、ERNIE 等

::: notes
常用的中文预训练模型有：哈工大讯飞联合实验室的中文 BERT-wwm、RoBERTa-wwm 系列（实验 8-3 用的 `hfl/rbt3` 是其中只有 3 层的小模型），百度的文心 ERNIE 系列等。它们可以从 Hugging Face、魔搭 ModelScope、飞桨 PaddleNLP 下载。
:::

## 8.3.3 文本任务的几种做法

| 做法 | 怎么做 | 优点 | 缺点 |
|---|---|---|---|
| 从零训练（实验 8-2） | 词向量和分类器都用自己的数据训练 | 模型小、速度快，CPU 就能跑 | 数据少时效果有限；难以理解复杂的语言 |
| 预训练模型微调（实验 8-3） | BERT 等模型接分类层，用自己的数据微调 | 效果通常明显更好，数据要求低 | 模型大，训练和使用最好有 GPU |
| 直接问大模型 | 把评论发给大语言模型，让它判断好评还是差评 | 不需要训练，甚至不需要标注数据 | 成本高、速度慢，结果需要抽查；数据安全要注意 |

## 8.5 前沿视窗
- 预训练模型越做越大：大语言模型
- 小模型仍有用：快、便宜
- 大模型帮忙标注，小模型上线

::: notes
中文预训练模型与大模型。BERT 之后，预训练模型越做越大：从 BERT 的 1 亿参数，到今天动辄几百亿、上千亿参数的大语言模型。国产大模型如百度文心、阿里通义千问、智谱 GLM、DeepSeek 等，都是在海量中文和多语言文本上预训练的 Transformer 解码器。它们不仅能分类，还能总结差评的原因、自动生成回复。大模型的原理、提示词和微调方法，在《自然语言处理导论》中详细学习。
小模型仍有用武之地。如果每天要处理上千万条评论，全部交给大模型，成本和速度都难以接受。常见的做法是“大模型帮忙标注，小模型负责干活”：先用大模型给几万条评论打上标签，再用这些数据训练一个像实验 8-2 这样的小模型，部署到线上。这也是一种知识的“迁移”。
:::
